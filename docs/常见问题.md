**按身份找入口**：

| 你是 | 先看 |

## 启动相关

### 双击启动图标没反应，或者窗口一闪就没了

先分清你双击的是哪一个：

| 双击的 | 在哪 | 说明 |
|---|---|---|
| `启动工作台.cmd` | **你自己的桌面/工作台目录** | 不是仓库自带的，是你（或帮你装的人）做的快捷方式 |
| `start-gui.bat` | 仓库的 `app\` 里 | 仓库自带的，能直接双击 |
| `start-local.ps1` | `app\` 里 | 真正的启动脚本，双击没用，要用 PowerShell 跑 |

**如果 `app\start-gui.bat` 双击也没反应**，说明是安装没完成，不是快捷方式的问题。

**原因**：这些启动器都是静默运行的（无黑窗设计），失败了也不会弹提示。

**怎么办**：手动跑一次启动脚本看错误：

```powershell
cd "你的工作台目录\主程序"     # 仓库版是 app\
powershell -NoProfile -ExecutionPolicy Bypass -File start-local.ps1
```

常见原因和对应处理：

| 报错 | 原因 | 处理 |
|---|---|---|
| `Bridge configuration is missing` | `.arena-gui\.env` 不存在 | 见下方「首次启动」 |
| `Desktop runtime is missing` | `node_modules\electron` 没装好 | `npm ci` 重新装 |
| 完全没输出就退出 | Electron 二进制缺失 | 见下方「Electron 起不来」 |

### Electron 起不来 / 一闪而过

**典型症状**：日志里什么都没有，或者只有一行
`Invalid file descriptor to ICU data received`。

**原因**：Electron 的运行时文件不全。完整的 `node_modules\electron\dist\`
应该有二十来个文件，包括：

```
electron.exe
icudtl.dat              ← 缺了这个必崩
resources.pak
chrome_100_percent.pak
chrome_200_percent.pak
v8_context_snapshot.bin
snapshot_blob.bin
...
```

**怎么办**：重新装 Electron。

```powershell
cd "你的工作台目录\主程序"
$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'
npm ci
# 如果 npm ci 没触发下载，手动跑：
node node_modules\electron\install.js
```

装完验证：

```powershell
Get-ChildItem node_modules\electron\dist -File | Measure-Object
# 应该是 15 个以上
```

> **重要**：`npm install` 会**清空整个 node_modules 重装**。
> 如果只是 Electron 有问题，优先用 `npm ci`（按 lock 文件精确还原），
> 不要在没备份的情况下乱动装包命令。

### 首次启动，`.env` 不存在

**直接跑安装脚本，它会自动生成：**

```powershell
cd "你的工作台目录\主程序"
powershell -ExecutionPolicy Bypass -File install-windows.ps1
```

> **注意路径**：配置文件必须在 `主程序\.arena-gui\.env`，
> **不是** `主程序\.env`，也不是 `.arena-gui\.env.example`。
>
> 仓库里的 `.env.example` 在 `app\` 根目录（`主程序\.env.example`），
> 那是**参考模板**，能直接复制，但复制到的目标必须是 `.arena-gui\.env`，
> 而且两个密钥留空是起不来的，得自己填。

**手动做的话：**

```powershell
$d = "主程序\.arena-gui"
New-Item -ItemType Directory -Path $d -Force | Out-Null
$b = New-Object 'byte[]' 32
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b)
$k = ($b | ForEach-Object { $_.ToString('x2') }) -join ''
@"
HOST=127.0.0.1
PORT=20140
ARENA_AGENT_BRIDGE_KEY=$k
STORAGE_ENCRYPTION_KEY=$k
ARENA_MCP_RUNTIME=local
ARENA_LOCAL_MCP_PORT=18766
ARENA_HEADED=1
ARENA_ARCHIVE_DIR=$(Resolve-Path $d)\archive
"@ | Set-Content "$d\.env" -Encoding utf8
```

（两个密钥用同一个串在本地够用，但正式用建议各生成一个。）

## 面板与界面

### 点「工作区」页签没反应

**原因**：左侧面板在 `http://127.0.0.1:20140/`（管理页），
工作区页在另一个地址。如果 20147 没起来，切换就会失败。

**怎么确认**：

```powershell
Get-NetTCPConnection -LocalPort 20147 -State Listen
# 有输出 = 在跑；报错 = 没起来
```

**怎么办**：

1. 看日志 `主程序\.arena-gui\desktop-shell.log`，找这一行：
   ```
   workspace server on 20147
   ```
   有这行说明服务器起来了；没有说明启动阶段就出错了。

2. 直接在浏览器打开 `http://127.0.0.1:20147/` 看能不能显示。

3. 都没有 → 关掉工作台重开。

> **背景**：Chromium 不允许 `http://` 页面导航到 `file://` 页面。
> 所以工作区页必须也用 HTTP 提供，不能直接用本地文件。

### 面板全黑 / 白屏

右侧官网正常但左侧空白。

**怎么办**：

1. 浏览器打开 `http://127.0.0.1:20140/` 看后端活着没
2. 看 `desktop-backend.log` 有没有报错
3. 后端没起来 → 在 `主程序/` 下跑 `node src/index.mjs` 看报什么错

### 面板宽度调不动

拖中间那条竖线。如果没反应，可能是 `divider` 视图没加载。

关掉重开一次。还不行说明 `divider.html` 文件损坏，从仓库重新拷一份。

## 账号相关

### 切换账号后一直显示「登录中」

**原因**：那个分区的登录态过期了，或者同步没生效。

**怎么办**：直接点「同步当前登录」重新注入 cookie。不用重新输密码。

### 认证过但提示「该会话属于另一个账号」

**原因**：你想打开的会话属于 A 号，但当前切在 B 号。

**怎么办**：先切到对应账号，再打开。

### 邮箱导入后重启就没了

**原因**：`mailboxes.dpapi` 解不开。

**可能的情况**：

| 情况 | 能否恢复 |
|---|---|
| 同机同用户，只是重启 | 能，正常读取 |
| 换了 Windows 用户 | 不能，DPAPI 绑定用户 |
| 重装系统 / 换电脑 | 不能 |
| 文件被删 | 不能，需重新导入 |

**怎么办**：重新导入一遍。原文件先留着（别删），万一能恢复。

### 账号太多，内存占满

每个账号 = 一个独立浏览器分区，都吃内存。

**怎么办**：

- 不常用的账号，用完把它的分区删掉（`.arena-gui/desktop-profile` 下对应目录）
- 或者减少同时活跃的账号数

## 抽卡相关

### 抽卡卡住不动

**可能原因**：

1. **右侧页面被占用** —— 你在手动操作官网，抽卡动不了
2. **网络断了** —— 探针发不出去
3. **Arena 改版** —— 页面结构变了，选择器失效

**怎么办**：

- 先确认右侧能正常手动对话
- 看 `desktop-backend.log` 有没有连续报错
- 连续失败 10 次会自动停，不会无限空转

### 抽卡时 API 返回「忙碌」

**这是设计如此，不是 bug。**

抽卡和 API 共用右侧那一个官网页面。同一时刻只能干一件事。

**怎么办**：等抽卡跑完再用 API，或者干脆不用 API 直接在工作台里操作。

### 识别结果不准 / 总是识别不出

**原因**：指纹识别是统计推断，本身有误差。

**改进办法**：

1. 把「每张几轮」从 1 调到 3——轮数越多证据越足
2. 点「检查并更新参考库」同步上游最新数据
3. 新模型刚出时参考库里可能还没有，识别不出是正常的

> **记住**：它是闭集推断，在已知模型列表里挑最像的。
> 不是「检测出真实身份」，是「看起来最像谁」。

### 「此任务成功了吗？」弹窗一直跳出来

**本来就该自动点掉的。** 如果一直弹，说明自动点掉的逻辑失效了
（Arena 改版导致选择器失效）。

**临时办法**：手动点掉。
**根治**：需要更新 `bridge.mjs` 里的选择器。

## 冷启动包相关

### 刚装完，「启动隧道」「发送到当前会话」两个按钮没反应 / 报「未找到打通教程」

**九成是这个原因：目录没按程序要求改名和搬文件。** 不是安装坏了。

程序里有四个路径是写死的（`main.cjs` 第 5 行 `TUNNEL_DIR`）：

| 按钮 | 它去找的文件 | 正确位置 |
|---|---|---|
| 启动 / 停止 / 状态 | `svc_ctl.ps1` | `隧道与MCP\bin\svc_ctl.ps1` |
| 接力包 | `relay_pack.py` | `隧道与MCP\bin\relay_pack.py` |
| 发送到当前会话 | `冷启动包-主.txt` | `隧道与MCP\冷启动包-主.txt` |
| 发送备用包 | `冷启动包-备用.txt` | `隧道与MCP\冷启动包-备用.txt` |

**一条命令全查完**：

```powershell
$r = "你的工作台根目录"      # 例：C:\Arena工作台
@(
  "$r\主程序\start-local.ps1",
  "$r\隧道与MCP\bin\svc_ctl.ps1",
  "$r\隧道与MCP\bin\relay_pack.py",
  "$r\隧道与MCP\冷启动包-主.txt",
  "$r\隧道与MCP\冷启动包-备用.txt"
) | ForEach-Object { "{0}  {1}" -f (Test-Path $_), $_ }
```

**必做三件事**（缺一不可）：

```powershell
# 1. app 改名 主程序，bridge 改名 隧道与MCP（已改过就跳过）
# 2. 两份 txt 搬进 隧道与MCP，并去掉文件名里的「躯壳版」
cd "$r\隧道与MCP"
Copy-Item .\冷启动包-躯壳版-主.txt   .\冷启动包-主.txt   -Force
Copy-Item .\冷启动包-躯壳版-备用.txt .\冷启动包-备用.txt -Force
# 3. 重启工作台（按钮读的是启动时的路径）
```

**如果你拿到的是别人打包好的工作台**，那这个结构应该已经是对的，
只需要查上面的五条 `Test-Path` 是不是全 `True`。

### 提示「未找到打通教程」（老版本现象）

**原因**：`冷启动包-主.txt` 找不到，或者内容格式不对。

**检查**：

```powershell
# 两个 txt 在工作台根目录下的「隧道与MCP」里
Test-Path "你的工作台目录\隧道与MCP\冷启动包-主.txt"
Test-Path "你的工作台目录\隧道与MCP\冷启动包-备用.txt"

# 内容应该有内容，不是空的
(Get-Content "你的工作台目录\隧道与MCP\冷启动包-主.txt" -Raw).Length
```

**注意**：这两个文件在 **`隧道与MCP\` 子目录里**，不在工作台根目录。
（早期版本在根目录，后来挪进了 `隧道与MCP\`。按钮读的就是子目录这一份，
所以只要按钮能发出去，文件位置就是对的。）

**还不行就搜一遍**：

```powershell
Get-ChildItem "你的工作台目录" -Recurse -Filter "冷启动包-*.txt" |
  Select-Object FullName, Length
```

### 发给 AI 后它没反应 / 说连不上

**先确认三样东西在跑**（工作区点「状态」看）：

```
[RUN ] Tunnel     PID=xxx
[RUN ] MCP local  PID=xxx (8765)
[RUN ] MCP fwd    PID=xxx
```

**如果状态里缺少某一项**：

```powershell
cd "你的工作台目录\隧道与MCP"
powershell -ExecutionPolicy Bypass -File bin\svc_ctl.ps1 -Action status
powershell -ExecutionPolicy Bypass -File bin\svc_ctl.ps1 -Action start -What all
```

### AI 说「我无法访问你的电脑」「我没有这个能力」

**先别信，也别急着改配置。** 先让它拿事实说话。

**原因**（按发生频率排）：

1. **它没测就下了结论。** 它按「网页 AI 一般不能执行本地命令」这个印象直接回答了你，
   而不是去跑包里的命令。这种情况最常见。
2. 隧道真的没起 —— 用下面「发给 AI 后它没反应」那节的三行状态确认。
3. 包没贴全 —— 它只收到了半截，缺了隧道参数。

**怎么办**：把这段发给它，逼它给原始输出：

```
按顺序跑这四条，每条都贴原始输出，不要总结、不要下结论：
1. ssh -F ~/.ssh/config <你的别名> whoami
2. P=$(grep -o '[0-9]*' ~/.arena-port 2>/dev/null | head -1); echo "port=$P"
3. curl -s -m 8 -X POST http://127.0.0.1:$P/mcp -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"c","version":"1"}}}'
4. 调 tools/list，数出一共有多少个工具
```

| 它的回答 | 结论 |
|---|---|
| 贴出了四条输出，工具数 36 | 通了，直接让它干活 |
| 某条报具体错误（`Permission denied` / `Connection refused` / `timed out`） | 真的有问题，按报错查对应章节 |
| 又是「我不能访问外部网络」但拿不出第 1、3 条的原始输出 | **它没测**。换一个模型或换一个对话，别在这上面耗 |

> 这一条写给两种人：装的人自己排查，和被求助的人。**「拿不出原始报错」和「报错」是两件事。**

### AI 说「tools/list 超时」

**这是正常现象，不是故障。**

MCP 协议要求先 `initialize` 再 `tools/list`。直接发 `tools/list` 服务器不会回包，
客户端就会超时。

冷启动包里已经写了这一条，AI 按它做就行。如果 AI 还在纠结这个，说明它没读懂包，
直接把包重发一次。

## 隧道与 MCP 相关

### 端口 8765 没在监听

```powershell
Get-NetTCPConnection -LocalPort 8765 -State Listen
```

没有输出 = MCP 服务没起来。

```powershell
cd "你的工作台目录\隧道与MCP"
powershell -ExecutionPolicy Bypass -File bin\svc_ctl.ps1 -Action start -What mcp
```

### 隧道断了

**注意**：隧道是**常驻**的，不是每轮重建的。如果断了：

```powershell
powershell -ExecutionPolicy Bypass -File bin\svc_ctl.ps1 -Action status
```

看输出里 `Tunnel` 那行的状态。需要重启就 `-Action start -What tunnel`。

### 看门狗没生效

检查计划任务：

```powershell
Get-ScheduledTask -TaskName "Arena Watchdog","Arena Service Launcher" | Format-Table TaskName,State
```

`State` 应该是 `Ready` 或 `Running`。如果是 `Disabled`：

```powershell
Enable-ScheduledTask -TaskName "Arena Watchdog"
```

## 代理相关

### 绑定了节点但没生效

1. 点「检测」看节点通不通
2. 确认绑定的是**当前账号**，不是别的账号
3. 重启工作台让配置生效

### 想用本机代理，不想导节点

直接在代理设置里填：

```
http://127.0.0.1:7890
```

端口改成你代理软件实际的 HTTP 端口。Clash 系列一般是 7890，
其他软件看它的设置页。

### 换了节点后账号还是要验证

**原因**：出口 IP 变了，Arena 判定为异常登录。

**怎么办**：这是风控的正常反应。做法是：

- 一个号固定一个节点，**不要频繁换**
- 换节点后重新登录一次，让 Arena 记住这个环境
- 别多个号共用同一个节点

## 性能相关

### 工作台很卡

**可能原因**：

| 原因 | 处理 |
|---|---|
| 打开太多账号分区 | 清理不用的 |
| 抽卡在跑 | 等它跑完 |
| 右侧官网页面很重 | 正常，Arena 页面本身就不轻 |
| 电脑在跑别的重活 | 检查任务管理器 |

### 磁盘占用越来越大

主要来自这几个地方：

| 目录 | 内容 | 能清吗 |
|---|---|---|
| `.arena-gui\archive\` | 模型归档 | 可以，删掉的会话也没了 |
| `.arena-gui\desktop-profile\` | 浏览器缓存 | 可以，会掉登录 |
| `.arena-gui\*.log` | 日志 | 可以，随时删 |
| `node_modules\` | 依赖 | 不能 |

## 怎么收集排障信息

需要找人帮忙看的时候，提供这几样：

```powershell
# 1. 进程和端口
Get-CimInstance Win32_Process -Filter "Name='electron.exe'" | Select-Object ProcessId,CommandLine
Get-NetTCPConnection -State Listen | Where-Object LocalPort -in 20140,20145,20147,8765

# 2. 主进程日志最后 30 行
Get-Content "主程序\.arena-gui\desktop-shell.log" -Tail 30

# 3. 后端日志最后 30 行
Get-Content "主程序\.arena-gui\desktop-backend.log" -Tail 30

# 4. Node 和 Electron 版本
node --version
(Get-Content "主程序\node_modules\electron\package.json" -Raw | ConvertFrom-Json).version
```

## 一个原则

**先看日志，再猜原因。**

这个项目的日志写得比较细，大部分问题看日志就能定位。
不要上来就重装——重装 `node_modules` 会清空整个依赖目录，
没备份的话可能把小问题变成大问题。
