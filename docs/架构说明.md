## 为什么是三个 WebContentsView

Electron 的 `WebContentsView` 可以理解成「嵌在窗口里的一块独立浏览器」。

工作台用了三个：

| 视图 | 加载什么 | 为什么独立 |
|---|---|---|
| **外壳页** `shell.html` | 顶部那一排按钮 | 只放 UI，不碰业务 |
| **左侧面板** | 管理页（20140）或工作区页（20147） | 需要 preload 桥接才能调主进程 |
| **右侧官网** | `https://arena.ai/agent` | 用独立的 session 分区，保证账号隔离 |

**为什么要分开**：右侧官网是外部网站，你把 preload 桥接给它，
等于把一个能操作你整台电脑的接口暴露给了外部页面。所以它**没有任何 preload**。

左侧面板是自己人，才给桥接。

中间那条竖线是第四个视图（`divider`），专门用来接收拖拽事件——
因为原生视图会盖住外壳页的 DOM，拖拽手柄只能单独放一层。

## 左侧面板为什么有两个端口

这是个值得记下来的坑。

| 端口 | 提供什么 |
|---|---|
| **20140** | 管理页（模型归档、连抽采集）+ OpenAI 兼容 API |
| **20147** | 工作区页（隧道状态、冷启动包、接力） |

**为什么不合并成一个**：因为面板需要在「管理」和「工作区」之间切换，
而工作区页原本是本地文件（`file://`）。

**问题在于**：Chromium 有一条硬规则——**由 `http://` 加载的页面，
不允许导航到 `file://` 页面**。面板一开始停在 `http://127.0.0.1:20140/`，
点「工作区」要跳到 `file:///.../workspace.html`，这一跳会被静默拒绝，
表现就是**点了没反应**。

**解法**：让主进程在 20147 起一个极简静态服务器，把 `workspace.html`
和它的两个资源也用 HTTP 提供。这样面板从 `http://20140` 跳到 `http://20147`，
是同协议跳转，畅通无阻。

那个服务器只监听 `127.0.0.1`，只白名单三个文件：

```
/            → workspace.html
/workspace   → workspace.html
/workspace.js → workspace.js
/shell.css   → shell.css
```

其他路径一律 404。

## 数据流：一次抽卡发生了什么

```
① 你在面板点「连抽采集」的开始
        │
        ▼  IPC: workbench → invoke('integration-control')
② Electron 主进程收到
        │
        ▼  HTTP: POST http://127.0.0.1:20140/api/harvest/start
③ 后端 server.mjs 收到，创建 Harvester 实例
        │
        ▼  Playwright 操作右侧官网页面
④ 创建新会话 → 发探针提示 → 等 AI 回答
        │
        ▼  从回答里提取数值特征
⑤ 和参考库比对，算出最像的模型
        │
        ├─ 没命中目标 → 回到 ④ 再发一轮
        │
        └─ 命中 → 
                │
                ▼  写入归档
⑥ 归档目录：
   主程序/.arena-gui/archive/<模型名>/
        ├─ 清单.md      这个模型下所有会话
        └─ 记录.json    结构化数据
                │
                ▼  把会话名改成 [指纹推测] xxx
⑦ 面板刷新，你看到新条目
```

**关键点**：抽卡全程操作的是**右侧那个真实的 Arena 页面**，
不是调用什么隐藏接口。所以抽卡时右侧会被占用，你没法同时手动对话。

## 数据都存哪

| 文件/目录 | 内容 | 加密 |
|---|---|---|
| `.arena-gui/.env` | 后端环境变量（密钥等） | 否（但权限受限） |
| `.arena-gui/credentials.json` | Arena 账号 cookie | 是（应用层 AES） |
| `.arena-gui/mailboxes.dpapi` | 邮箱池 | 是（Windows DPAPI） |
| `.arena-gui/proxies.dpapi` | 代理节点与绑定关系 | 是（Windows DPAPI） |
| `.arena-gui/desktop-settings.json` | 窗口尺寸、当前账号等杂项 | 否 |
| `.arena-gui/archive/` | 模型归档（清单 + 记录） | 否 |
| `.arena-gui/desktop-profile/` | 浏览器分区（cookie、缓存） | 浏览器自身机制 |
| `.arena-gui/desktop-shell.log` | 主进程日志 | 否 |
| `.arena-gui/desktop-backend.log` | 后端日志 | 否 |

### 两种加密方式的区别

**DPAPI**（`*.dpapi` 文件）：

- 加密密钥由 Windows 系统托管，绑定**当前用户 + 当前机器**
- 换电脑、重装系统、换 Windows 用户 → **解不开**
- 优点：不需要你记密码
- 缺点：不可迁移

**应用层 AES**（`credentials.json`）：

- 密钥存在 `.env` 里（`STORAGE_ENCRYPTION_KEY`）
- 理论上可以迁移，但 `.env` 丢了同样解不开

> **实践建议**：这两个 `.dpapi` 文件里的东西（邮箱、代理）本质上是可以重建的，
> 丢了重新导入一遍就行，不用太紧张。真正要紧的是 `credentials.json` 和 `.env`。

### 排障时先看日志

主进程出问题看 `desktop-shell.log`，里面都是这种行：

```
2026-11-04T09:29:45.150Z process started
2026-11-04T09:29:45.204Z main ready
2026-11-04T09:29:45.424Z workspace server on 20147
2026-11-04T09:29:45.547Z shell loaded
2026-11-04T09:29:46.538Z panel loaded
```

后端出问题看 `desktop-backend.log`。

## 隧道与 MCP 这一层

### 为什么需要它

Arena 的网页 AI 跑在云端，它碰不到你本机的文件。

「隧道 + MCP」做的事：**给你本机开一个云端 AI 能访问的入口。**

```
云端 AI 想读你的文件
      ↓
它调用 MCP 工具（read_file）
      ↓
请求经隧道回到你的 Windows
      ↓
本机 MCP 服务执行，把结果送回去
```

### 组件

| 组件 | 路径 | 作用 |
|---|---|---|
| **MCP 服务** | `bridge/desktop_mcp.py` | 36 个工具，监听 8765 |
| **服务控制** | `bridge/svc_ctl.ps1` | 启停、状态、自愈 |
| **看门狗** | 计划任务 `Arena Watchdog` | 定时检查，挂了自动拉起 |
| **开机自启** | `bridge/autostart.vbs` | 无黑窗启动 |
| **反向隧道** | SSH | Windows 主动连 VPS，把 8765 映射过去 |

**注意方向**：是 **Windows 主动连出去**，不是 VPS 连进来。
所以家里没有公网 IP、有 NAT、有防火墙都没关系。

### 36 个工具都有什么

| 类别 | 数量 | 代表工具 |
|---|---|---|
| 文件/命令 | 6 | `read_file` `list_dir` `search_text` `file_edit` `exec_command` |
| 扩展 | 11 | `read_image` `file_write` `glob_files` `exec_bg` `read_pdf` `web_fetch` |
| 浏览器 | 9 | `browser_start` `browser_open` `browser_act` `browser_shot` |
| 桌面 | 7 | `screenshot` `mouse_click` `keyboard_type` `keyboard_hotkey` |
| 会话接力 | 3 | `session_list` `session_read` `session_relay` |

完整列表在工作区点「状态」会打印出来。

### 自愈逻辑

`svc_ctl.ps1` 不是简单的 start/stop，它带判断：

```
调用时先检查：
  ├─ 隧道进程在吗？端口通吗？      → 不在就重建
  ├─ MCP 进程在吗？8765 在听吗？   → 不在就拉起
  ├─ 有残留会话吗？                → 清理掉
  └─ 配置文件完整吗？              → 缺就报明确的错
```

所以冷启动包里让 AI 直接调它就行，不用 AI 自己写判断逻辑。

## 冷启动包是什么

`冷启动包-主.txt` 和 `冷启动包-备用.txt` 是两份**写给 AI 看的说明书**。

不是给你看的，是给 AI 看的。里面写着：

- 「本机三样东西常开，直接当它在，不要问用户开没开」
- 「先 initialize 再 tools/list，直接发 tools/list 会超时」
- 「失败不要报错、不要停、不要问，继续下一步」
- 「只有 9 步全走完还不通，才允许说一句话」

**为什么要这样设计**：AI 有个通病——遇到小挫折就停下来请示用户。
这份文件就是提前把这条路径堵死，让它自己走完。

**主包 vs 备用包**：主包假设私钥已就位，直接用；备用包走公钥路径，
用在私钥不可用或者给别人装机的场景。

## 几个容易踩的坑

**1. preload 的权限是按协议和端口分的**

`workspace-preload.cjs` 里，`file:` 协议给全部能力，`http://20147` 给工作区需要的
14 个动作，`http://20140` 只给 `open-session` 和 `panel-resize`。

**为什么要分**：右侧官网是外部内容，万一它嵌套了面板的 preload，也不能让它
调 `exec_command`。这是纵深防御。

**2. 冷启动包在 隧道与MCP 里，不在工作台主目录**

`main.cjs` 第 5 行定义 `TUNNEL_DIR = 工作台根\隧道与MCP`，第 262 行从这里读：

```js
const tut = fs.readFileSync(path.join(TUNNEL_DIR,'冷启动包-主.txt'),'utf8');
```

备用包在第 153、156 行，同一个目录。所以两份 txt 必须放在
`工作台根\隧道与MCP\` 下，**且文件名叫 `冷启动包-主.txt` / `冷启动包-备用.txt`**
（不带「躯壳版」三个字）。

**同理，`TUNNEL_DIR` 还派生了另外三个被写死的路径**：

| 用途 | 完整路径 |
|---|---|
| 启动/停止/状态 | `隧道与MCP\bin\svc_ctl.ps1` |
| 接力包 | `隧道与MCP\bin\relay_pack.py` |
| 接力包用的 Python | `隧道与MCP\.venv\Scripts\python.exe` |

**这四个路径一个字都不能改**——改目录名或者少放一个文件，
工作台上对应的按钮就会静默失效或报「未找到打通教程」。

**3. 抽卡和 API 抢同一个页面**

右侧只有一个官网视图。抽卡时它在跑探针，API 请求进来只能返回「忙碌」。

**4. 指纹库不联网也能用**

`bank.json` 是内置的快照。断网时用这个，点更新才会去拉上游。
